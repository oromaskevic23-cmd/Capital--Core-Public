# Security and responsible disclosure

This public documentation repository provides no production SLA or certification.

## Reporting a vulnerability

Use GitHub **Security → Report a vulnerability** when that private reporting option is available for the repository. Its availability must be checked in GitHub; this document does not claim it is enabled.

If a private report option is unavailable, open a non-sensitive issue requesting a confidential reporting channel. Do not include exploit details, secrets, customer data or infrastructure addresses in the public issue. Wait for an agreed private channel before sharing sensitive details. No response-time guarantee is made.

## Scope

Report the affected repository, revision and a minimal description sufficient to arrange private triage. Test only systems you own or are explicitly authorized to assess. Do not run destructive tests or expand scope.

Zero Trust, Deny by Default, Fail Closed, AI Passport, Guardian Core, Approval Gateway and Audit Ledger remain architectural governance requirements. Public documentation is not permission to bypass them.

## Disclosure and release

Maintain a dated record of report, triage, corrective revision and verification. Publish only reviewed, redacted evidence. Existing public-history exposure requires a separate history and credential review; removing current text does not erase old commits.
