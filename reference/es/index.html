VISIÓN GLOBAL · CONOCIMIENTO LOCAL

Capital Core · Enterprise

El objetivo: un equipo de Nano Core Agents universales dedicado a cada gran ciudad del mundo. Conocimiento local, capacidades profesionales e inteligencia compartida dentro de Federated Multi-Orchestrator Architecture.

Hoja de ruta arquitectónica · Los equipos locales están previstos; no se ha verificado una cobertura mundial activa.

01

Cada ciudad tiene su contexto

Los equipos estudian mercados, idiomas, sectores y oportunidades de negocio locales con fuentes fechadas e información verificable.

02

Equipos universales. Facultades definidas.

Los equipos NCA dinámicos combinan investigación, análisis empresarial, ingeniería de software y operaciones. Las capacidades y los permisos se asignan por misión; la versatilidad no concede autoridad ilimitada.

03

ORION · inteligencia colectiva

ORION conecta el conocimiento de los equipos locales, compara conclusiones y prepara recomendaciones. Facilita el aprendizaje compartido; los orquestadores de dominio siguen siendo responsables de la ejecución autorizada.

04

Ejecución federada

Los orquestadores de dominio coordinan misiones de distintas organizaciones y equipos profesionales dentro de Runtime Domains. AI Passport, Enterprise IMPERIAL Skills, Guardian Core, Approval Gateway y Audit Ledger mantienen la trazabilidad.

Capital Core aporta inteligencia económica y empresarial. El análisis financiero no autoriza transacciones; CRYPTO IMPERIAL Ecosystem mantiene su límite separado.

01

Estructura principal

Arquitecto → HANTER → capa federada de orquestadores → Runtime Domains → Nano Core Agents → ejecución controlada → verificación → Audit Ledger. Alexander Romaskevich es el fundador, propietario, CEO y la autoridad arquitectónica final.

02

HANTER

Centro de mando de IA y adjunto del Arquitecto: inteligencia ejecutiva, descomposición de misiones, planificación, delegación, coordinación y recopilación de evidencias. No se convierte en un orquestador global todopoderoso, no depende de NERO y no puede ampliar sus privilegios ni reescribir las protecciones fundamentales.

03

Arquitectura canónica

Federated Multi-Orchestrator Architecture: múltiples orquestadores, cada uno vinculado a su Runtime Domain y a Nano Core Agents autorizados. La cantidad de orquestadores y agentes es dinámica; no hay un único orquestador global.

04

Nano Core Agents

Agentes especializados con AI Passport, rol, Runtime Domain, capacidades, Enterprise IMPERIAL Skills, política vinculada, presupuesto, contexto de misión e identidad de auditoría. Áreas posibles: software, seguridad, investigación, finanzas, derecho, operaciones, infraestructura y negocio.

05

Cadena de seguridad

AI Passport → Enterprise IMPERIAL Skills → Guardian Core → Approval Gateway → Runtime Domain → límite de ejecución → Audit Ledger. Identidad ≠ Autoridad. Capacidad ≠ Aprobación. Inteligencia ≠ Privilegio.

06

AI Passport

Identifica al agente sin otorgarle un derecho incondicional a actuar. Campos mínimos: passport_id, agent_id, role, runtime_domain, capabilities, policy_version, issued_at, expires_at, status, cryptographic_identity.

07

Enterprise IMPERIAL Skills

Módulos controlados de capacidades profesionales. Cada Skill define capacidades, entradas, herramientas permitidas, acciones prohibidas, Runtime Domain, aprobación necesaria, privilegios, plazo, presupuesto y requisitos de evidencia y auditoría.

08

Guardian Core

Puerta principal de políticas y seguridad. Verifica identidad, capacidad, política, riesgo y protección humana antes de ALLOW, DENY o APPROVAL. Principio: Fail Closed; denegar cuando no se cumplen las condiciones.

09

Approval Gateway

Comprueba si esta acción exacta está autorizada para este agente en este momento. Estados: ALLOW, DENY, REQUIRE_APPROVAL, REVOKED, EXPIRED. La ausencia de decisión implica DENY.

10

Audit Ledger

Vincula misión, agente, AI Passport, política, autorización, ejecución, resultado y evidencias. Debe permitir demostrar quién actuó, qué se autorizó, qué política regía, qué se ejecutó realmente y qué resultado se obtuvo.

11

Zero Trust

Una red de confianza no convierte a un agente en fiable. Un agente conocido no está autorizado automáticamente. Una aprobación anterior no sustituye la actual; instalar un Skill no autoriza la ejecución; superar una prueba no demuestra preparación para producción. Verificar cada acción privilegiada.

12

Runtime Domains

Zonas de ejecución que aíslan agentes, herramientas, datos, secretos, presupuestos, políticas, capacidades e infraestructura. El acceso entre dominios se deniega por defecto y requiere autorización explícita.

13

TETRIS

Capa de seguridad de ejecución: Security Kernel, Tool Execution Firewall, Agent Behavior Firewall, Target Containment, Evidence Lifecycle, Classification Controls y Kill Switch. Objetivo: limitar el impacto de un agente que falla o está comprometido.

14

IMPERIAL AGI

Componente separado: razonamiento → crítica → verificación → evidencias → recomendación. No sustituye a HANTER, no es un orquestador global y no recibe autoridad de ejecución automática. Respeta los límites canónicos de confianza.

15

ISMG

IMPERIAL Sovereign Model Gateway conecta agentes con modelos. Incluye validación de AI Passport, autorización, registros de proveedores, modelos y capacidades, enrutamiento, control de presupuesto, Secret Broker, Audit Adapter y Kill Switch. Es una pasarela, no un centro de mando.

16

Legion

Componente separado de IMPERIAL Core: participación distribuida, ecosistema de agentes y orquestadores y aislamiento de Runtime Domains. Sin autoridad universal; cada participante sigue la cadena canónica de seguridad.

17

ORION

Componente independiente con límites propios, contratos explícitos de integración y autoridad federada. No existe acceso implícito de superusuario.

ORION conecta el conocimiento de los equipos locales, compara conclusiones y prepara recomendaciones. Facilita el aprendizaje compartido; los orquestadores de dominio siguen siendo responsables de la ejecución autorizada.

18

Capital Core

Subsistema de inteligencia económica y empresarial. Inteligencia financiera ≠ autoridad para transacciones ≠ ejecución de transacciones.

El objetivo: un equipo de Nano Core Agents universales dedicado a cada gran ciudad del mundo. Conocimiento local, capacidades profesionales e inteligencia compartida dentro de Federated Multi-Orchestrator Architecture. Enterprise ↗

19

CRYPTO IMPERIAL Ecosystem

Límite arquitectónico separado que comprende NDB, IMPERIUM, EconomicCapability, BudgetPolicy, PaymentIntent, AuthorizationDecision y PaymentReceipt.

20

IMPERIUM

Visión arquitectónica a largo plazo de una moneda digital para agentes de IA de todo el mundo. No demuestra adopción mundial, uso actual, liquidez de mercado, pagos generalizados ni dominio económico en producción.

21

Ejecución económica

PaymentIntent → AI Passport → EconomicCapability → BudgetPolicy → Guardian Core → Approval Gateway → AuthorizationDecision → ejecución → PaymentReceipt → Audit Ledger. Denegar intenciones caducadas, repeticiones, nonces duplicados, cambios de importe, destinatario o política, pasaportes o dominios incorrectos, capacidades no autorizadas, presupuesto insuficiente y transferencias de autoridad entre agentes.

22

Public / Private Boundary

Público: arquitectura, especificaciones, repositorios, evidencias verificables y documentación oficial. Privado: código propietario, secretos, credenciales, infraestructura de ejecución, políticas internas, controles privilegiados y configuración de seguridad. Una afirmación arquitectónica no demuestra una implementación.

23

Protección humana

Protección humana > objetivo comercial > autonomía del sistema > objetivo del agente. Se prohíben el daño deliberado, la manipulación coercitiva, la represión, el uso como arma contra personas y la captura de gobernanza. La IA no reescribe las protecciones fundamentales.

24

Kill Switch

Detención selectiva de agente, capacidad, misión, Runtime Domain, modelo, proveedor o actividad económica; control de emergencia del sistema. Desactivar el nivel mínimo necesario para contener el problema.

25

Niveles de evidencia

E0: arquitectura. E1: especificación. E2: implementación. E3: verificación estática y unitaria. E4: integración. E5: verificación en ejecución. E6: evidencia de producción. Ningún nivel se eleva sin pruebas.

26

Matriz Fail Closed

UNKNOWN, MISSING, INVALID, EXPIRED, REVOKED o MISMATCH → DENY. Una condición desconocida, ausente, inválida, caducada, revocada o incompatible no concede autorización.

27

Flujo de ejecución

Arquitecto → HANTER → Mission Envelope → orquestador federado → Nano Core Agent → AI Passport → Enterprise IMPERIAL Skill → Guardian Core → Approval Gateway → Runtime Domain → TETRIS → ISMG / herramienta / servicio → ejecución → verificador → Audit Ledger → evidencias.

28

10 reglas inviolables

1. Ningún orquestador global. 2. Denegación por defecto. 3. Sin identidad, no hay ejecución. 4. Sin capacidad, no hay ejecución. 5. Sin aprobación, no hay ejecución privilegiada. 6. Sin autoescalada de privilegios. 7. Sin autoridad silenciosa entre dominios. 8. Sin autoridad económica por inteligencia solamente. 9. Sin afirmar producción sin evidencias. 10. La IA no reescribe la protección humana.

29

Fórmula principal

Identidad → capacidad → política → aprobación → aislamiento → ejecución → verificación → evidencias. Por encima: protección humana, autoridad arquitectónica, Zero Trust y auditabilidad.
