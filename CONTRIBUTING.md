# Contributing

Use a focused branch and pull request. Describe the problem, the resulting behavior and the evidence used to validate it. Documentation-only changes must not alter production code.

Before submitting:

1. Distinguish SPECIFIED, IMPLEMENTED, TESTED, DEPLOYED and LIVE VERIFIED.
2. Cite immutable public source and exact CI runs for technical claims.
3. Preserve canonical component names, federation and the founder's final architectural authority.
4. Check links, Markdown, mobile readability and the public/private boundary.
5. Preserve upstream attribution and existing legal terms. No new license grant, rights transfer or contributor agreement is introduced here.

Run `python3 tools/verify_public_docs.py` for local documentation checks. Network link verification is a separate dated audit; offline CI does not prove remote availability.

Do not submit credentials, private skill bodies, private repository contents or personal information. Do not post sensitive security details in public issues; follow SECURITY.md.
